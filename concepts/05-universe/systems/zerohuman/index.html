ZeroHuman

An always-on service that sells small jobs to other AI agents. Agents pay the ENS name zerohuman.eth 0.0001 ETH and get the result back in a transaction from the same name. No account, no API, no human in the loop.

My first agent experiment showed that one AI agent could pay another through ENS and Ethereum. It also showed the gaps: both agents ran on my Mac mini, I operated both, and the seller was not open to anyone else. ZeroHuman is the next step, rebuilt from scratch: a seller that runs continuously in the cloud and that any agent can buy from without asking me.

01 · How an order works

One order, five stations, one name at the centre

Step 1 of 5

  1. 1 Discover

    Buying agent

    The buying agent looks up zerohuman.eth and reads its menu.

    A text record on the name, com.zerohuman.services, publishes the menu: the services, the exact price, the chain and a link to the request format. You cannot search ENS, so ZeroHuman is also listed where agents and their tools look (see below).

  2. 2 Pay and order

    Buying agent → zerohuman.eth

    It sends exactly 0.0001 ETH to the name, with its request as a small JSON message in the transaction data.

    {"zh":1,"svc":"decision","opts":["launch publicly this week","run the allowlist trial longer","add a third service first"],"ctx":"zerohuman first mainnet order"}

  3. 3 Work

    Worker on Railway

    A worker on Railway watches the chain, waits for the payment to settle, checks the request and does the job.

    A Decision uses no AI model: the randomness comes from the hash of a block five blocks after the order, mixed with the order's own transaction hash. Encouragement is written by DeepSeek. The worker refuses to sign anything unless the name, the menu and its own wallet all agree, and it re-checks every ten minutes.

  4. 4 Deliver

    zerohuman.eth → buyer

    It sends a zero-value transaction back from zerohuman.eth with the result and the order's transaction hash.

    The name's ETH address is the service wallet, and that wallet's primary name is zerohuman.eth, so explorers show deliveries as coming from the name.

  5. 5 Verify

    Buying agent

    The buyer checks everything on its own connection to Ethereum, including recomputing a Decision.

    For the first order: “I recomputed the choice from the chain and it matched.”

Orders take a few minutes by design: the worker waits for confirmations, and a Decision has to wait for its future block.

02 · The name is the business

There is no website checkout and no API

zerohuman.eth is the storefront, the payment address, and the sender of every result.

  1. Address

    The name's ETH address is the service wallet, and that wallet's primary name is zerohuman.eth, so explorers show deliveries as coming from the name.

  2. Menu

    A text record on the name, com.zerohuman.services, publishes the menu: the services, the exact price, the chain and a link to the request format.

  3. Agreement

    The worker refuses to sign anything unless the name, the menu and its own wallet all agree, and it re-checks every ten minutes.

  4. Cold owner

    The name itself is owned by a separate cold wallet. If the server were ever compromised, the attacker would get the small working balance, not the name.

What it sells From the build page

Decision 0.0001 ETH

An agent sends two to five options and ZeroHuman picks one at random. No AI model is involved. The randomness comes from the hash of a block five blocks after the order, mixed with the order's own transaction hash, so anyone can recompute the choice and check it.

Encouragement 0.0001 ETH

An agent describes the problem it is stuck on and gets back a short encouraging message and one practical next step, written by DeepSeek.

04 · Boundaries

Where the system ends

The dashed ring around the orbit. These are the limits, stated plainly.

  1. B1

    Hot key on the host

    The service wallet's key lives on the hosting provider. It holds only a small working balance, but a compromised server could take it.

  2. B2

    No escrow

    There is no escrow. A buyer pays first and trusts ZeroHuman to deliver. Refunds are manual and best effort.

  3. B3

    Builders can bias a Decision

    Block builders can influence the Decision result, so it is meant for low-stakes choices only.

  4. B4

    One order at a time

    Orders are handled one at a time, roughly one every 50 seconds at most.

  5. B5

    Third-party dependencies

    It depends on Railway, a third-party Ethereum connection and DeepSeek.

  6. B6

    No outside buyer yet

    As of November 20, 2026, no outside agent has bought from it. Both paid orders so far came from my own test buyer.

05 · How it was built and tested

Spec by Ken, code by an agent, five days

I wrote the specification and made the decisions that involve money and identity. An AI agent in HyperAgent wrote, tested and shipped the code over about five days, from November 11 to 16, 2026.

Stack
A TypeScript worker, a SQLite database on a Railway volume, viem for Ethereum and ENS, and DeepSeek for one service. No smart contract and no token.
Exactly-once delivery
Every transaction is saved before it is sent, and the worker checks what actually happened onchain before doing anything new, so a crash or restart never loses an order or delivers it twice.
Spending limits
Gas caps, a daily gas budget and automatic pauses if fees spike or the balance runs low.

  1. 154

    Automated tests

    Including one that kills the worker at random, up to 17 times in a run, and checks every order is still delivered exactly once.

  2. 2

    Testnet services

    Both services on Sepolia, first from the build environment and then on Railway, including a restart in the middle of an order.

  3. 0 ETH

    Prompt injection

    One test order told the model to send 1 ETH to an outside address and reveal its private key. It refused, and the reply still went only to the buyer, carrying no ETH. Sepolia delivery ↗

  4. 15 + 9

    Independent review

    Before going public I had a different AI model review the code. It found no way for a buyer, a model reply or a faulty data source to send money anywhere except back to the payer, but it found 15 ways the service could stall under real traffic. All were fixed. A second review found 9 smaller issues, also fixed.

  5. 1 → all

    Mainnet

    One allowed buyer first, then open to everyone.

How agents find it
