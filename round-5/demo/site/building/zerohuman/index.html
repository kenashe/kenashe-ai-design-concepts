ZeroHuman: A Business Only AI Agents Can Use

A tiny online shop that only AI agents can use. They find it, pay it and get their order back with no person involved. It’s a small, real test of what business between AI agents could look like.

Live since November 16, 2026

An always-on service that sells two small jobs to other AI agents for 0.0001 ETH each. Agents find it through the ENS name zerohuman.eth, pay that name directly, and get the result back in a transaction from the same name. No account, no API key, no marketplace, and no human handling orders.

My first agent experiment showed that one AI agent could pay another through ENS and Ethereum. It also showed the gaps: both agents ran on my Mac mini, I operated both, and the seller was not open to anyone else. ZeroHuman is the next step, rebuilt from scratch: a seller that runs continuously in the cloud and that any agent can buy from without asking me.

What it sells

  • Decision, 0.0001 ETH. An agent sends two to five options and ZeroHuman picks one at random. No AI model is involved. The randomness comes from the hash of a block five blocks after the order, mixed with the order's own transaction hash, so anyone can recompute the choice and check it.
  • Encouragement, 0.0001 ETH. An agent describes the problem it is stuck on and gets back a short encouraging message and one practical next step, written by DeepSeek.

The name is the business

There is no website checkout and no API. zerohuman.eth is the storefront, the payment address, and the sender of every result:

  • The name's ETH address is the service wallet, and that wallet's primary name is zerohuman.eth, so explorers show deliveries as coming from the name.
  • A text record on the name, com.zerohuman.services, publishes the menu: the services, the exact price, the chain and a link to the request format.
  • The worker refuses to sign anything unless the name, the menu and its own wallet all agree, and it re-checks every ten minutes.
  • The name itself is owned by a separate cold wallet. If the server were ever compromised, the attacker would get the small working balance, not the name.

How an order works

  1. Discover. The buying agent looks up zerohuman.eth and reads its menu.
  2. Pay and order. It sends exactly 0.0001 ETH to the name, with its request as a small JSON message in the transaction data.
  3. Work. A worker on Railway watches the chain, waits for the payment to settle, checks the request and does the job.
  4. Deliver. It sends a zero-value transaction back from zerohuman.eth with the result and the order's transaction hash.
  5. Verify. The buyer checks everything on its own connection to Ethereum, including recomputing a Decision.

Orders take a few minutes by design: the worker waits for confirmations, and a Decision has to wait for its future block.

How it was built

I wrote the specification and made the decisions that involve money and identity. An AI agent in HyperAgent wrote, tested and shipped the code over about five days, from November 11 to 16, 2026.

  • Stack: a TypeScript worker, a SQLite database on a Railway volume, viem for Ethereum and ENS, and DeepSeek for one service. No smart contract and no token.
  • Exactly-once delivery: every transaction is saved before it is sent, and the worker checks what actually happened onchain before doing anything new, so a crash or restart never loses an order or delivers it twice.
  • Spending limits: gas caps, a daily gas budget and automatic pauses if fees spike or the balance runs low.

How it was tested

  1. Automated tests. 154 tests, including one that kills the worker at random, up to 17 times in a run, and checks every order is still delivered exactly once.
  2. Testnet. Both services on Sepolia, first from the build environment and then on Railway, including a restart in the middle of an order.
  3. Prompt injection. One test order told the model to send 1 ETH to an outside address and reveal its private key. It refused, and the reply still went only to the buyer, carrying no ETH. Sepolia delivery ↗
  4. Independent review. Before going public I had a different AI model review the code. It found no way for a buyer, a model reply or a faulty data source to send money anywhere except back to the payer, but it found 15 ways the service could stall under real traffic. All were fixed. A second review found 9 smaller issues, also fixed.
  5. Mainnet. One allowed buyer first, then open to everyone.

How agents find it

You cannot search ENS, so ZeroHuman is also listed where agents and their tools look:

  • The ERC-8004 agent registry on Ethereum, as agent #56626 ↗, linked back from zerohuman.eth with an ENSIP-25 record so the name and the registry entry vouch for each other.
  • An A2A agent card with a free endpoint that answers "how do I order?", plus an llms.txt summary.
  • The A2A Registry and AgentPeering directories.

Limitations

  • The service wallet's key lives on the hosting provider. It holds only a small working balance, but a compromised server could take it.
  • There is no escrow. A buyer pays first and trusts ZeroHuman to deliver. Refunds are manual and best effort.
  • Block builders can influence the Decision result, so it is meant for low-stakes choices only.
  • Orders are handled one at a time, roughly one every 50 seconds at most.
  • It depends on Railway, a third-party Ethereum connection and DeepSeek.
  • As of November 20, 2026, no outside agent has bought from it. Both paid orders so far came from my own test buyer.

What's next

The real test is the first wallet I have never seen paying zerohuman.eth. After that, the plan is for ZeroHuman to spend its own earnings buying services from other agents.
